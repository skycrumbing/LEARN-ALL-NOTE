# 数据压缩与香农编码 (Data Compression & Shannon Coding)

> 一句话定位：压缩 = 让每个符号的实际码长去逼近它的信息量 `-log₂p`。熵 H 就是无损压缩的理论下限——你再聪明也压不过它。霍夫曼/香农-范诺就是"怎么配码长让平均码长最小"的具体操作。
> 前置阅读：`information-theory.md`（信息量、熵）。
> 串回：`conditional-entropy-mutual-information.md`、`mle.md`、神经网络 loss。

---

## 一、接回第一站的钩子

第一站说过：单个事件信息量 `I(p) = -log₂p` = "最少几次二分能确定它"。比如 `p = 1/8`，`-log₂(1/8) = 3`，正好 3 次二选一问出结果。

数据压缩问的正是这件事的另一面：

> 如果某个符号出现的概率是 `p`，那给它分配比特时，**它至少配得上 `-log₂p` 个比特**。

**越常见（p 大）→ `-log p` 小 → 配的比特少。越罕见（p 小）→ `-log p` 大 → 配的比特多。** 这就是"把短的码给高频的词"——所有压缩算法的核心直觉。汉字输入法的简码、摩斯电码（E 是 `.`，Q 是 `--.-`）都是这个道理。

## 二、朴素配对法，熵就出来了

假设 4 个符号 A、B、C、D，各自概率：

```
符号  概率 p   需求比特 -log₂p
A    0.5       1
B    0.25      2
C    0.125     3
D    0.125     3
```

**朴素做法**：4 个符号用固定 2 比特（`00 01 10 11`）。每条消息 2 比特，不管 A 多常见。

**聪明做法**：把短的码给高频的 A。

```
A → 0        (1 bit)
B → 10       (2 bit)
C → 110      (3 bit)
D → 111      (3 bit)
```

平均每条消息多少比特？——**按概率加权平均**：

```
平均码长 L = Σ p(outcome) × 码长
           = 0.5×1 + 0.25×2 + 0.125×3 + 0.125×3
           = 0.5 + 0.5 + 0.375 + 0.375
           = 1.75 比特
```

这就是 `Σ p × (-log₂p)`——**这正是熵 `H`**。

所以：
- 固定编码 → 2 比特
- 变长编码（短的给高频）→ 1.75 比特 = **正是熵**

### 结论第一发

**平均码长不可能比熵更低。熵 = 压缩的理论下限。** 你再聪明，也压不过熵。

## 三、变长编码有个致命问题——解码

上面那套 `0 / 10 / 110 / 111` 有个坑：收到一串 `0110`，能确定是 `0(A) 110(C)` 还是别的？解码会糊。

需要**前缀码（prefix-free）**：一个字不能被另一个字的前缀。检查：

```
0     — 是任何别的码的前缀吗？否（别的码都不是 0 开头除了 0 本身）
10    — 0 不是它的前缀；1 不是任何码的开头歧义。OK
110   — 
111   —
```

没有一个码是另一个的前缀，所以收到一串比特，能**没有歧义地"分岔"解码**。这正好对应：霍夫曼树里**每个叶子一条码，内部节点没有任何码**，天然满足前缀性。

## 四、霍夫曼编码——贪心造树，保证平均码长 = 熵（近似）

问题变成：怎么自动给任意概率集配出一套**最短平均码长**的**前缀码**？

**霍夫曼的招（贪心 + 树）**：

```
准备：n 个符号当 n 个叶子，权重 = 概率
步骤（重复）：
  1. 挑两个概率最小的节点
  2. 合并成一个父节点，权重 = 两者之和
  3. 左枝标 0，右枝标 1
  4. 放回，继续，直到只剩一棵树
```

用 A(0.5) B(0.25) C(0.125) D(0.125) 走一遍：

```
第一轮：最小两个是 C(0.125)、D(0.125)
        合并成节点 CD(0.25)，左枝 0(→C)，右枝 1(→D)
当前集合：A(0.5)  B(0.25)  CD(0.25)

第二轮：最小两个是 B(0.25)、CD(0.25)
        合并成 BCD(0.5)，B=0分支，CD=1分支
当前集合：A(0.5)  BCD(0.5)

第三轮：合并 A 和 BCD 成根(1.0)，A=0分支，BCD=1分支

根
├─0─ A(0.5)          码: 0
└─1─ BCD
    ├─0─ B(0.25)     码: 10
    └─1─ CD
        ├─0─ C(0.125)  码: 110
        └─1─ D(0.125) 码: 111
```

得到的码正好是第二节那套 `0/10/110/111`，平均码长 1.75 = 熵。

**霍夫曼最优性**（直觉不证明）：贪心每次合并最小的两个，保证高频符号留在浅层、得到短码；低频符号沉到深处拿到长码。结果**平均码长最短**，且**永远在 [H, H+1)** 区间内（每个符号编码浪费不到 1 个比特）。

## 五、香农-范诺——另一种做法

比霍夫曼更早、更直观的是**香农-范诺编码**：按概率降序排列，把符号尽量均匀地切成两半，每半给 1 个 bit。

```
A(0.5)  0 | 0     → A: 0
B(0.25)    1 | 0  → B: 10     (0.5 那半再加 1 位)
C(0.125)      | 0 → C: 110
D(0.125)      | 1 → D: 111
```

这例子里跟霍夫曼结果一样。香农-范诺更直观，但**可能不是最优**（有时平均码长比霍夫曼长一点点）。霍夫曼是工程上更优的那个。

## 六、一个数字把整条线兜住

回头看整条线其实是一个数字的不断变形：

```
信息量 I(p) = -log₂p           单个符号值多少比特
熵     H    = Σ p·I(p)          平均每个符号最少需要多少比特（压缩下限）
平均码长 L  = Σ p·(实际码长)     你用编码实际发的比特
霍夫曼        让 实际码长 ≈ -log₂p，所以 L 尽量 ≈ 熵 H
```

**压缩 = 让每个符号的实际码长去逼近它的信息量 `-log₂p`。** 霍夫曼/香农-范诺就是"怎么给符号配码长、让 Σp·码长 最小"的具体操作。香农第一定理的雏形就在这：**熵是无损压缩的下限。**

---

## 七、一句话总结

**高频给短码（直觉）→ 通过树/前缀码消歧 → 霍夫曼（贪心最优）/香农-范诺（直观）→ 平均码长 `L = Σ p·(码长)`，熵 `H = Σ p·(-log p)` 是理论下限 → 结论：`H ≤ L`，压缩压不过熵。**
