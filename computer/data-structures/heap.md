# 堆（Heap）

> 堆是一棵**用数组存储的完全二叉树**，满足"父节点 ≥/≤ 子节点"的堆序性质。
> 插入、删除堆顶均为 O(log n)，取最值 O(1)。
> 它是 JDK `PriorityQueue`、线程池定时任务队列 `DelayedWorkQueue`、Top-K 问题的核心结构。

## 一、什么是堆

### 两条规定定义一个堆

```
规定 1：结构性 —— 必须是完全二叉树
        除最后一层外每层都满，最后一层从左到右排列（可以不满）

规定 2：堆序性 —— 父子之间有大小关系
        大顶堆：父 ≥ 子      （堆顶 = 全局最大值）
        小顶堆：父 ≤ 子      （堆顶 = 全局最小值）
```

```
大顶堆示例：                 小顶堆示例：

         50                       10
        /  \                     /  \
      30    40                 20    15
     / \   / \                / \   / \
   20  25 35 38             25  30 18  22

检查堆序性（大顶堆）：
  50 ≥ 30, 40 ✅
  30 ≥ 20, 25 ✅
  40 ≥ 35, 38 ✅

注意：兄弟之间无大小要求！
  20 和 25 谁大无所谓，只要都 ≤ 30 就行
  → 堆只保证"全局最值在堆顶"，不保证整体有序
```

### 堆 vs 二叉搜索树

| | BST / 红黑树 | 堆 |
|---|---|---|
| 有序性 | 整体有序（左 < 根 < 右），可中序遍历出有序序列 | 只有父子偏序，兄弟无序 |
| 找最小值 | O(log n)（一路向左） | **O(1)**（就是堆顶） |
| 找最大值 | O(log n)（一路向右） | **O(1)**（大顶堆堆顶） |
| 找任意值 | O(log n) | O(n)（只能遍历！） |
| 删除最值 | O(log n) | O(log n) |
| 用途 | 查找、范围查询 | 反复取最值（优先级队列） |

> **定位一句话**：堆是"只会取最值的懒人树"——牺牲任意查找能力，换取最值 O(1) + 维护成本极低。

### 常见误区："叔侄无序"——堆到底约束了什么？

用一个具体例子看清堆的约束边界：

```
合法大顶堆 [50, 40, 30, 35]：

        50(0)
       /     \
     40(1)   30(2)
    /
  35(3)

逐对检查所有父子关系（堆序性唯一约束的东西）：
  ✅ 50 ≥ 40    （0 和 1）
  ✅ 50 ≥ 30    （0 和 2）
  ✅ 40 ≥ 35    （1 和 3）

全部满足 → 合法大顶堆
```

**反直觉的地方**：

```
35 比 30 大，可它却在"更靠后/更低"的位置 —— 合法吗？

  合法。因为 30 和 35 是"叔侄"关系，不是父子：
    30 是 50 的右孩子
    35 是 40 的左孩子

  堆的规则：
    父子必须有序：父 ≥ 子        ← 唯一硬约束
    兄弟随意：    40 和 30 谁大都行
    叔侄随意：    30 < 35 完全没问题

  极端情况：叔叔可以比侄子小。
  堆只保证"从任何节点往上走到根，一路非递增"，
  从不保证跨子树的大小关系。
```

**数组视图的疑惑**：

```
数组 [50, 40, 30, 35] 中，30 后面跟着更小的... 不对，是更大的 35，
看起来"乱序"？—— 下标相邻的两个元素之间没有任何大小约定。

数组的下标只是"寻址公式"的输入：
  parent(i) = (i - 1) / 2
  left(i)   = 2i + 1
  right(i)  = 2i + 2

30(2) 和 35(3) 在数组里相邻，
但在树上一个在右子树、一个在左子树内，八竿子打不着。
```

**对比：什么时候才真的违反？**

```
同样这个堆，如果插入的是 45：

      50                    50
     /  \                  /  \
   40    30    → 上浮 →  45    30     ← 45 > 父 40，交换一次
   /                     /
  45(新插入)            40

判断标准只有一条：新节点是否大于它的【父亲】
  插入 35：35 ≤ 40 → 不动
  插入 45：45 > 40 → 换一次
  插入 55：55 > 40 且 > 50 → 连换两次到顶
```

| 关系 | 堆管吗 | 本例 |
|------|--------|------|
| 父 ≥ 子 | ✅ 管 | 40 ≥ 35 ✅ |
| 兄弟之间 | ❌ 不管 | — |
| 叔侄之间 | ❌ 不管 | 30 < 35 完全合法 |
| 数组相邻元素 | ❌ 不管 | 下标只是寻址工具 |

> **堆的本质承诺只有一条**：任何一条"从叶到根"的路径是有序的，跨路径的一切都不保证。
> 这也是为什么堆找最值 O(1)，但找任意元素只能 O(n) 全遍历——它根本不知道 35 藏在哪条路径上。

## 二、为什么用数组存

### 完全二叉树的天然优势：没有空洞

```
完全二叉树逐层编号，恰好连续填满数组：

  数组: [50, 30, 40, 20, 25, 35, 38]
  index  0   1   2   3   4   5   6

           50(0)
          /      \
       30(1)     40(2)
       /   \      /   \
    20(3) 25(4) 35(5) 38(6)

下标公式（0-based）：

  parent(i) = (i - 1) / 2     ← 向下取整
  left(i)   = 2i + 1
  right(i)  = 2i + 2

验证：
  节点 30 在 index 1
    parent = (1-1)/2 = 0 → 50 ✅
    left   = 2×1+1 = 3 → 20 ✅
    right  = 2×1+2 = 4 → 25 ✅

这些公式不是"规定"，而是层序存储的必然结果：
每个父亲名下固定占两个连续席位，
节点 i 之前有 i 个父亲 → 已消耗 2i 个席位 → 孩子从 2i+1 开始坐。
完整推导见 ../algorithms/integer-rounding.md 场景 1b。
```

### 对比链式存储

| | 链式二叉树 | 数组堆 |
|---|---|---|
| 每节点开销 | 2 个指针（16B）+ 对象头 | 无指针，纯数据 |
| 访问子/父 | 解引用跳转 | **下标计算**，一步到位 |
| CPU 缓存 | 指针跳跃，缓存不友好 | 数组连续内存，缓存友好 |
| 内存局部性 | 差 | ⭐ 好 |

> 这和[红黑树 vs B+树](red-black-tree.md#十红黑树-vs-b+树存储介质决定数据结构)的结论呼应：
> **紧凑的数组结构永远比指针跳跃的结构更亲缓存。**
> B+树把节点做成页，堆直接把整棵树做成数组——同一思想的两种形态。

## 三、上浮与下沉：两个核心动作

堆的全部操作只靠两个动作维持堆序性：

### 上浮（Swim / Sift-Up）：向上找位置

```
场景：节点比自己父亲大（大顶堆）→ 违反堆序 → 往上换

初始状态（60 是新插入到末尾的，违反堆序）：

        50(0)
       /     \
     30(1)   40(2)
     /
   60(3)   ← 新插入，60 > 父 30 ❌ 违反大顶堆

Step 1: 60(index 3) 和父节点 30(index 1) 比较 → 60 > 30 → 交换

        50
       /  \
     60    40     ← 60 升到 index 1
     /
   30             ← 30 落到 index 3

   60 继续向上比较父节点

Step 2: 60(index 1) 和父节点 50(index 0) 比较 → 60 > 50 → 交换

        60          ← 60 到顶，结束 ✅
       /  \
     50    40     ← 50 落到 60 原来的位置（index 1）
     /
   30             ← 30 不动（还在 index 3）

注意：每次只比较"60 当前所在位置"和它的父节点，
     其余节点的相对位置不因交换而改变。
     最终整棵树满足：60 ≥ 50,40 且 50 ≥ 30 ✅

上浮路径 = 从插入点到根的一条线 → 最多走树高次 = O(log n)
```

```java
// 上浮：第 k 个元素向上移动到正确位置（大顶堆）
private void swim(int[] heap, int k) {
    while (k > 0 && heap[(k - 1) / 2] < heap[k]) {
        // 父 < 我 → 交换，我升到父的位置
        swap(heap, k, (k - 1) / 2);
        k = (k - 1) / 2;
    }
}
```

### 下沉（Sink / Sift-Down）：向下找位置

```
场景：节点比自己孩子小（大顶堆）→ 违反堆序 → 往下换

      10   ← 堆顶太小（常见于删除后把尾部元素挪上来）
     /  \
   30    40

Step 1: 选两个孩子中【较大】的那个比较
        max(30, 40) = 40 → 40 > 10 → 交换

      40
     /  \
   30    10
            ↓ 继续和自己的孩子比
Step 2: 10 是叶子，无孩子 → 结束

为什么选较大的孩子？
  要保证换上去的是"两个孩子中更能当爹的"
  选小的那个换上来，另一边立即违反堆序

下沉路径 = 从节点到叶子的一条线 → 最多走树高次 = O(log n)
```

```java
// 下沉：第 k 个元素向下移动到正确位置（大顶堆）
private void sink(int[] heap, int k, int size) {
    while (2 * k + 1 < size) {              // 有左孩子才继续
        int child = 2 * k + 1;               // 先假设左孩子较大
        if (child + 1 < size && heap[child] < heap[child + 1]) {
            child++;                          // 右孩子更大就选右
        }
        if (heap[k] >= heap[child]) break;   // 我 ≥ 较大孩子 → 堆序满足
        swap(heap, k, child);                // 否则和较大孩子交换
        k = child;
    }
}
```

## 四、插入操作

```
两步走：
  ① 把新元素追加到数组末尾（保持完全二叉树形状）
  ② 上浮到正确位置

为什么先放末尾再上浮？
  直接插中间会破坏完全二叉树结构（出现空洞）
  末尾追加永远保持形状合法，堆序交给上浮修复
```

```java
public void offer(int value) {
    heap[size++] = value;   // ① 追加到末尾
    swim(heap, size - 1);   // ② 上浮
}
```

```
插入演示（大顶堆，依次插入 50, 30, 60, 20）：

offer(50):  [50]
            无需上浮（根）

offer(30):  [50, 30]
            30 ≤ 50，无需上浮

offer(60):  [50, 30, 60]
            60 > 父 50 → 上浮交换 → [60, 30, 50]

            60
           /
         30    ← 50 被挤到右子

offer(20):  [60, 30, 50, 20]
            20 < 父 30，无需上浮

            60
           /  \
         30    50
        /
      20
```

## 五、删除堆顶操作

堆只支持删堆顶（最值），这是它的设计定位。

```
三步走：
  ① 记下堆顶值（返回用）
  ② 把数组末尾元素搬到堆顶（保持完全二叉树形状）
  ③ 堆顶下沉到正确位置

为什么不能直接删掉堆顶让空位留在那？
  会破坏完全二叉树结构！必须用末尾元素补位。

为什么搬末尾元素而不是搬较大的孩子上来？
  搬孩子上来会在中间留洞，连锁反应复杂；
  搬末尾元素只产生一个需要下沉的点，一次搞定。
```

```java
public int poll() {
    int top = heap[0];          // ① 取堆顶
    heap[0] = heap[--size];     // ② 末尾补位
    sink(heap, 0, size);        // ③ 下沉
    return top;
}
```

```
删除演示（大顶堆 [60, 30, 50, 20]）：

poll():

  ① top = 60

  ② 末尾 20 补到堆顶：
        20
       /  \
     30    50
     /
   (20 已从末尾移除)

  ③ 下沉：
     20 的孩子 max(30, 50) = 50 → 50 > 20 → 交换
        50
       /  \
     30    20
     20 成为叶子，结束

结果：[50, 30, 20]，堆顶变为剩余最大值 50 ✅
```

> 连续 poll 就能按降序不断取出元素——这正是**堆排序**的原理。

## 六、建堆：O(n) 而不是 O(n log n)

给定乱序数组，如何变成堆？

### 笨方法 vs 聪明方法

```
笨方法：逐个插入 + 上浮
  第 k 个元素上浮代价 O(log k)
  总代价 = O(log 1 + log 2 + ... + log n) = O(n log n)


聪明方法：从最后一个非叶子节点开始，倒序逐个下沉
  叶子节点天然是合法堆（无孩子），跳过
  只处理非叶子节点：index 从 n/2 - 1 倒数到 0
```

```java
public void buildHeap(int[] arr) {
    // 从最后一个非叶子节点开始，倒序下沉
    for (int i = arr.length / 2 - 1; i >= 0; i--) {
        sink(arr, i, arr.length);
    }
}
```

### 建堆过程图解

以乱序数组 `[4, 6, 8, 5, 9]`（n = 5）为例：

**Step 0：确定谁需要下沉**

```
初始状态（完全不是堆）：

        4(0)
       /    \
     6(1)   8(2)
    /   \
  5(3)  9(4)

定位非叶子节点：
  叶子 = 左孩子下标越界的节点：index 2, 3, 4（共 3 个 = ⌈5/2⌉）
       └─ index 2 的"孩子"应是 index 5、6，都越界 → 8 也是叶子！
  非叶子 = index 0, 1
  最后一个非叶节点 = n/2 - 1 = 5/2 - 1 = 1

循环范围：i = 1 → 0，倒序执行
```

**Step 1：i = 1，下沉节点 6**

```
        4                比较 6 的两个孩子：
       / \                  max(5, 9) = 9 > 6 → 与 9 交换 ↓
     [6]   8
     / \              交换后：
    5   9                 6 落到叶子位置，无孩子，本轮结束
                          （只花了 1 次交换）

        4
       / \
      9   8
     / \
    5  [6]

数组变化：[4, 6, 8, 5, 9] → [4, 9, 8, 5, 6]
此时：左子树 {9,5,6} 已是合法堆 ✅
```

**Step 2：i = 0，下沉节点 4（可能连沉多层）**

```
第一轮比较：
        [4]               max(9, 8) = 9 > 4 → 与 9 交换 ↓
       /  \
      9    8            数组：[4, ...] → [9, 4, 8, 5, 6]
     / \
    5   6

第二轮比较（4 沉到 index 1 后继续）：
         9
       /  \              4 的新孩子是 5(index 3)、6(index 4)
      [4]   8            max(5, 6) = 6 > 4 → 与 6 再交换 ↓
      / \
     5   6             数组：[9, 4, ...] → [9, 6, 8, 5, 4]

最终结果：
         9              ← 到叶子，结束
        / \
       6    8           堆序验证：
      / \                 9 ≥ 6, 8 ✅
     5   4                6 ≥ 5, 4 ✅  合法大顶堆！

总代价：Step 1 花 1 次 + Step 2 花 2 次 = 3 次交换
对比 n log n 上限：5 × log5 ≈ 11 次 —— 实际远小于上界
```

### 为什么必须倒序（从后往前）？

```
sink() 有一个隐藏前提：【被下沉节点的两棵子树必须已经是合法堆】

        4          对根做 sink 时，要拿 4 和 max(子树最大者) 比，
       / \         这个比较成立的前提是：
      ?   ?        左子树内部有序、右子树内部有序
     / \           —— 否则换上来的可能不是整个子树的最大值
    ?   ?

倒序处理恰好保证了这一点：

  i = n/2-1（最底层的父亲）
    它的孩子全是叶子 → 叶子天然是合法堆 → sink 合法 ✅
  i = n/2-2, ..., 0（逐层向上）
    处理每个节点时，它的子树都已被之前轮次修好 → sink 合法 ✅

如果正着来（i = 0 开始）：
  一上来就对根下沉，但左右子树还是乱的
  → 换上来的不是子树最大值 → 结果根本不是堆 ❌
```

> **一句话记忆**：建堆像"从地基往上盖楼"——先把最小的子结构修成堆，
> 上一层才能放心地只处理自己这一个点。倒序不是性能技巧，是**正确性要求**。

### 为什么是 O(n)？—— 高度加权求和

```
关键洞察：大部分节点在底层，而底层的节点几乎不用下沉！

n 个节点的完全二叉树中：
┌──────────┬─────────────┬──────────────┐
│ 高度 h    │ 节点数       │ 单个下沉代价   │
├──────────┼─────────────┼──────────────┤
│ 0(叶子)   │ ~n/2        │ 0 次（不下沉） │
│ 1        │ ~n/4        │ ≤ 1 次        │
│ 2        │ ~n/8        │ ≤ 2 次        │
│ 3        │ ~n/16       │ ≤ 3 次        │
│ ...      │ ...         │ ...           │
│ log n(根) │ 1           │ ≤ log n 次    │
└──────────┴─────────────┴──────────────┘

总代价 = Σ (该高度节点数 × 最大下沉次数)
       ≈ n/2 × 0 + n/4 × 1 + n/8 × 2 + n/16 × 3 + ...

设 S = n/4 + 2n/8 + 3n/16 + ...
用错位相减法（两边同乘 1/2 再相减）：

  S     =  1·n/4 + 2·n/8 + 3·n/16 + ...
  S/2   =          1·n/8 + 2·n/16 + ...
  ─────────────────────────────────────
  S - S/2 = n/4 + n/8 + n/16 + ...  = n/2
  ∴ S = n

总建堆代价 = O(n)  ✅

直观记忆："少数节点多干活，多数节点少干活，
           加权平均下来每人只干常数次"
```

> **面试考点**：建堆 O(n) vs 逐个插入 O(n log n)，区别就在
> "自底向上下沉（多数节点代价低）" vs "自顶向上浮（每个都可能走到顶）"。

## 七、时间复杂度总表

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| 查看堆顶 `peek` | O(1) | 数组第一个元素 |
| 插入 `offer` | O(log n) | 追加 + 上浮 |
| 删除堆顶 `poll` | O(log n) | 补位 + 下沉 |
| **建堆** `buildHeap` | **O(n)** | 倒序下沉，高度加权 |
| 堆排序 `heapSort` | O(n log n) | 建堆 O(n) + n 次 poll |
| 查找任意元素 | O(n) | 堆不支持！只能遍历 |

## 八、典型应用场景

### 场景 1：优先队列（JDK PriorityQueue）

```
任务调度、事件驱动模拟、Dijkstra 最短路……
凡是"每次取出优先级最高的"，都是堆的主场。

JDK 的 java.util.PriorityQueue 底层就是一个数组小顶堆，
核心源码就是 siftUp / siftDown 两个方法。
```

### 场景 2：定时任务 —— 你已经学过的知识串联

```
还记得线程池笔记中的 ScheduledThreadPoolExecutor 吗？

  computer/thread-pool/source-analysis.md

它的 DelayedWorkQueue 底层就是【小顶堆】：

  ├── 堆顶 = 到期时间最早的任务
  ├── 工作线程 loop 里 take() 时：
  │     若堆顶还没到期 → awaitNanos(剩余时间) 挂起等待
  │     到期了 → poll() 弹出执行
  ├── 新任务提交 → offer() 入堆 + 上浮
  └── 为什么用堆不用红黑树？
        只需要"取最早到期的"，正是堆的定位；
        不需要按任意 key 查找/范围查询，BST 能力浪费。
```

### 场景 3：Top-K 问题（面试最高频）

```
题目：100 万个数，找出最大的 K 个（如 K=10）

错误思路：全排序 O(n log n) —— 浪费，我们只要前 K 个

正确思路：维护一个【大小为 K 的小顶堆】
  ① 前个数直接入堆
  ② 后续每个数 x 与堆顶比较：
       x > 堆顶（当前 K 个中最小的）→ 弹堆顶，入 x
       x ≤ 堆顶 → 跳过
  ③ 结束时堆里就是最大的 K 个

复杂度：O(n log K)  ← 注意是 log K 不是 log n！

反直觉点：找最大的 K 个，用的却是小顶堆？
  因为堆顶要放"K 个候选中门槛最低的"，方便随时淘汰它。
  找最小的 K 个 → 大顶堆。方向相反，逻辑对称。
```

### 场景 4：合并 K 个有序链表

```
LeetCode 23：k 条有序链表合成一条

  小顶堆放 k 个链表的当前头结点
  每次 poll 出最小者接到结果链，再把它的 next 入堆
  复杂度：O(N log K)，N=总节点数，K=链表条数
```

### 场景 5：双堆求动态中位数（进阶）

```
数据流持续到来，随时询问中位数：

  大顶堆 A（放大的一半，堆顶=下半区最大）
  小顶堆 B（放小的一半，堆顶=上半区最小）

  保持 A.size == B.size 或多 1
  → 中位数 = A.top 或 (A.top + B.top)/2，全程 O(log n)

LeetCode 295「数据流的中位数」标准解法。
```

## 九、完整 Java 实现

```java
import java.util.Arrays;

/**
 * 大顶堆（数组实现）
 * 支持 offer / poll / peek / buildHeap / heapSort
 */
public class MaxHeap {

    private int[] heap;
    private int size;

    public MaxHeap(int capacity) {
        heap = new int[Math.max(capacity, 16)];
        size = 0;
    }

    /** 用现成数组建堆：O(n) */
    public MaxHeap(int[] arr) {
        heap = Arrays.copyOf(arr, arr.length);
        size = arr.length;
        buildHeap();
    }

    // ===== 建堆：从最后非叶节点倒序下沉 =====
    private void buildHeap() {
        for (int i = size / 2 - 1; i >= 0; i--) {
            sink(i);
        }
    }

    // ===== 插入：追加 + 上浮 =====
    public void offer(int value) {
        if (size == heap.length) grow();
        heap[size] = value;
        swim(size);
        size++;
    }

    // ===== 取最大：堆顶补位 + 下沉 =====
    public int poll() {
        if (size == 0) throw new IllegalStateException("heap is empty");
        int top = heap[0];
        heap[0] = heap[--size];
        sink(0);
        return top;
    }

    public int peek() {
        if (size == 0) throw new IllegalStateException("heap is empty");
        return heap[0];
    }

    public int size() { return size; }

    // ===== 上浮 =====
    private void swim(int k) {
        while (k > 0 && heap[(k - 1) / 2] < heap[k]) {
            swap(k, (k - 1) / 2);
            k = (k - 1) / 2;
        }
    }

    // ===== 下沉 =====
    private void sink(int k) {
        while (2 * k + 1 < size) {
            int child = 2 * k + 1;                       // 左孩子
            if (child + 1 < size && heap[child] < heap[child + 1]) {
                child++;                                  // 选较大的孩子
            }
            if (heap[k] >= heap[child]) break;
            swap(k, child);
            k = child;
        }
    }

    private void swap(int i, int j) {
        int t = heap[i];
        heap[i] = heap[j];
        heap[j] = t;
    }

    private void grow() {
        heap = Arrays.copyOf(heap, heap.length * 2);
    }

    // ===== 附赠：堆排序（原地，O(n log n)）=====
    public static void heapSort(int[] arr) {
        // ① 建大顶堆 O(n)：复用下沉逻辑
        int n = arr.length;
        for (int i = n / 2 - 1; i >= 0; i--) {
            sinkStatic(arr, i, n);
        }
        // ② 反复取最大放到数组尾部 O(n log n)
        for (int end = n - 1; end > 0; end--) {
            int t = arr[0];
            arr[0] = arr[end];
            arr[end] = t;
            sinkStatic(arr, 0, end);   // 剩余部分重新下沉
        }
    }

    private static void sinkStatic(int[] arr, int k, int size) {
        while (2 * k + 1 < size) {
            int child = 2 * k + 1;
            if (child + 1 < size && arr[child] < arr[child + 1]) child++;
            if (arr[k] >= arr[child]) break;
            int t = arr[k]; arr[k] = arr[child]; arr[child] = t;
            k = child;
        }
    }
}
```

### 使用示例

```java
public class Main {
    public static void main(String[] args) {
        // 1. 基本操作
        MaxHeap h = new MaxHeap(16);
        h.offer(50);
        h.offer(30);
        h.offer(60);
        h.offer(20);
        System.out.println(h.peek());   // 60
        System.out.println(h.poll());   // 60
        System.out.println(h.peek());   // 50

        // 2. 乱序数组建堆 O(n)
        MaxHeap h2 = new MaxHeap(new int[]{4, 6, 8, 5, 9});
        System.out.println(h2.peek());  // 9

        // 3. Top-K：100 万个数里找最大的 3 个
        int[] data = {3, 100, 45, 87, 21, 999, 65, 12, 340, 78};
        java.util.PriorityQueue<Integer> min =
            new java.util.PriorityQueue<>();          // JDK 小顶堆
        int K = 3;
        for (int x : data) {
            if (min.size() < K) {
                min.offer(x);
            } else if (x > min.peek()) {
                min.poll();
                min.offer(x);
            }
        }
        System.out.println(min);        // [340, 999, 87] 顺序无关，集合即答案

        // 4. 堆排序
        int[] arr = {4, 6, 8, 5, 9, 1, 7};
        MaxHeap.heapSort(arr);
        System.out.println(java.util.Arrays.toString(arr));  // 升序
    }
}
```
