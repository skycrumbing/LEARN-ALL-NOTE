# Java IO 体系全景

## 一、Java IO 的演变

```
BIO (1.0) → NIO (1.4) → AIO (1.7)
```

| 版本 | IO 类型 | 核心类 | 模型 |
|------|---------|--------|------|
| JDK 1.0 | BIO | `InputStream` / `OutputStream` / `Socket` | 阻塞同步 |
| JDK 1.4 | NIO | `Channel` / `Buffer` / `Selector` | 非阻塞同步 |
| JDK 1.7 | AIO | `AsynchronousSocketChannel` | 异步非阻塞 |

## 二、核心问题：一个线程能同时处理多少个连接？

这是 IO 模型演变的核心驱动力：

```
BIO：  一个线程 = 一个连接（线程数爆炸）
NIO：  一个线程 = N 个连接（多路复用）
AIO：  一个线程 = N 个连接（异步回调，零阻塞）
```

## 三、BIO 的致命瓶颈

假设你的服务器要处理 10,000 个并发连接：

```java
// BIO 模型：每个连接一个线程
while (true) {
    Socket client = serverSocket.accept();  // 阻塞
    new Thread(() -> handle(client)).start();  // 10000 个线程！
}
```

- **线程栈内存**：每个线程默认栈 1MB → 10000 线程 = 10GB 内存
- **上下文切换**：CPU 在线程间频繁切换，性能急剧下降
- **资源耗尽**：线程数超过系统限制（`ulimit -u`）

> **结论**：BIO 在高并发场景下不可行，必须引入多路复用。

## 四、NIO 的突破：多路复用

```
         用户态                    内核态
   ┌─────────────┐          ┌──────────────┐
   │   Selector   │  poll    │   Epoll/Kqueue │
   │  (一个线程)  │◄────────►│   (内核事件表)  │
   └──────┬──────┘          └──────────────┘
          │                       │
          │  读取事件              │  accept / read / write
          │  可写事件              │
          ▼                       ▼
   ┌─────────────┐          ┌──────────────┐
   │  处理数据     │◄────────│   网络数据     │
   │  (仍然同步)   │  read()  │   socket     │
   └─────────────┘          └──────────────┘
```

- **一个线程** 通过 `Selector` 同时监控 10,000 个 Channel 的 IO 事件
- 有事件才处理，没有事件线程就等待（不会被阻塞在某个连接上）
- **仍然有阻塞**：`read()` / `write()` 时线程仍会阻塞，只是不会被 `accept()` 卡住

## 五、AIO 的理想：真正的异步

```
   ┌─────────────┐
   │  提交异步任务  │
   │  (不阻塞)     │
   └──────┬──────┘
          │  注册回调
          ▼
   ┌─────────────┐
   │  CompletionHandler │
   │  completed(...)    │── 成功时调用
   │  failed(...)       │── 失败时调用
   └─────────────┘
```

- 发起 IO 请求后**立即返回**，不等待结果
- 操作系统完成 IO 后，**回调**通知线程处理
- 真正的 **异步非阻塞**，线程数几乎不随连接数增长

> **注意**：AIO 在 Linux 上底层基于 `eventfd` + `signalfd`，性能不如 NIO + Epoll，所以生产环境 Netty 仍然基于 NIO。

## 六、总结一张图

```
连接数:  100      1,000      10,000      100,000
         │          │           │           │
BIO:    ✅         ⚠️          ❌         ❌
NIO:    ✅         ✅          ✅         ✅
AIO:    ✅         ✅          ✅         ✅ (但 Linux 上实际不如 NIO)

生产选型:  大部分场景 → NIO (Netty)
```
