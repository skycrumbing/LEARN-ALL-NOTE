# 并查集（Union-Find / Disjoint Set Union）

> 并查集是一种维护**动态连通性**的数据结构——高效回答"元素 x 和 y 是否属于同一组"，
> 并支持"把两个组并成一个"。
> 配合路径压缩 + 按秩合并，单次操作均摊复杂度 O(α(n))，**几乎是常数时间**。

## 一、它解决什么问题

### 经典场景：朋友圈

```
有 8 个人，已知一些朋友关系（朋友的朋友也是朋友）：

  1-2  3-4  5-6  2-3  7-8

问题：
  Q1: 1 和 4 是不是朋友？（要顺关系链推导）
  Q2: 一共有几个朋友圈？

暴力做法（每次查询都 BFS/DFS）:
  每次查询 O(n)，n 次查询 O(n²)

并查集的做法:
  动态维护"谁和谁同组"，每次查询 O(α(n)) ≈ O(1)
```

### 抽象成两个操作

```
并查集维护若干个【互不相交的集合】，支持：

  1. union(x, y)   合并：把 x 和 y 所在的两个集合并成一个
  2. find(x)       查询：x 所在集合的【代表元】（根）
  3. connected(x,y) 查询：x 和 y 是否同一集合
                    = find(x) == find(y)

附加：
  4. count()       查询：当前有几个集合
```

## 二、核心思想：用树表示集合

```
每个集合用一棵树表示，根节点是这个集合的"代表元"。

  集合 A: {1, 2, 3, 7}
              1           ← 根 = 代表元
             / \
            2   3
           /
          7

  集合 B: {4, 5, 6}
              4           ← 根 = 代表元
             / \
            5   6


判断两个元素是否同组 = 它们的根是否相同
  find(7) → 1
  find(5) → 4
  1 ≠ 4 → 不同组
```

### 用数组存这棵"森林"

```
parent[] 数组：parent[i] = 节点 i 的父节点
  根节点的 parent[i] = i（自己指向自己）

  index:   1  2  3  4  5  6  7  8
  parent:  1  1  1  4  4  4  2  8
           ↑  ↑  ↑  ↑           ↑
          根  指向1 指向1 根    指向2(节点7的父是2) 单独

对应森林：
        1            4           8
       / \          / \
      2   3        5   6
     /
    7
```

> 这种"数组存森林"和 [堆](../data-structures/heap.md) 的"数组存完全二叉树"是同一种思想，
> 但寻址方式不同：
> - 堆：靠**下标公式** `parent(i) = (i-1)/2` 找父亲（树形固定）
> - 并查集：靠 **parent 数组**直接查表找父亲（树形动态变化）

## 三、两个基础操作

### 3.1 find：一路往上找根

```java
// 找 x 的根（代表元）
int find(int x) {
    while (parent[x] != x) {
        x = parent[x];   // 往上走一步
    }
    return x;
}
```

```
find(7) 的执行过程：

  parent[7] = 2   → 7 不是根，走到 2
  parent[2] = 1   → 2 不是根，走到 1
  parent[1] = 1   → 1 是根！返回 1

  路径: 7 → 2 → 1，走了 3 步
```

> ⚠️ 如果树退化为链，find 要走 O(n)。这是后面要优化的核心问题。

### 3.2 union：把两棵树合并

```java
// 合并 x 和 y 所在的集合
void union(int x, int y) {
    int rootX = find(x);
    int rootY = find(y);
    if (rootX == rootY) return;   // 已同组，无需合并

    // 把 rootY 挂到 rootX 下（朴素做法）
    parent[rootY] = rootX;
}
```

```
union(3, 5)：合并 {1,2,3,7} 和 {4,5,6}

  合并前:                    合并后:
        1                        1
       / \                      /|\
      2   3          →         2 3 4
     /                          /  / \
    7                          7  5   6
        4
       / \
      5   6

  find(3) = 1, find(5) = 4
  把根 4 挂到根 1 下：parent[4] = 1
```

## 四、两个关键优化

朴素版有两个性能陷阱，两个优化各击破一个。

### 4.1 优化一：路径压缩（Path Compression）

**问题**：find 沿链走，链越长越慢。

```
find(7) 要走 7→6→5→4→3→2→1，共 6 步
        1
        |
        2
        |
        3
        |
        4
        |
        5
        |
        6
        |
        7
```

**优化**：find 时，把沿途所有节点**直接挂到根**，把链"拍扁"。

```java
// 递归版：最简洁
int find(int x) {
    if (parent[x] != x) {
        parent[x] = find(parent[x]);  // 递归找根，顺便把当前节点直接挂到根
    }
    return parent[x];
}
```

```
find(7) 执行过程（拍扁前后）:

  拍扁前（长链）:              拍扁后:
        1                        1
        |                      / | | | | |
        2                     2  3  4  5  6  7
        |
        3
        |        ──────►
        4
        |
        5
        |
        6
        |
        7

  find(7) 走过的路径: 7→6→5→4→3→2→1
  路径压缩把这 6 个节点（2,3,4,5,6,7）全部直接挂到根 1 下

  之后再 find(7): parent[7] = 1，一步到位！
  之后再 find(2..6): 同样一步到位
```

> **本质**：第一次 find 多花点时间把链拍扁，后续所有 find 都是 O(1)。
> 典型的"用一次开销换长期高效"——和红黑树的旋转、跳表的随机层数是同一种思路。

### 4.2 优化二：按秩合并（Union by Rank）

**问题**：朴素 union 总是把一棵树挂到另一棵下面。如果总是把大树挂小树下，树会越来越高。

```
糟糕的合并方式（大树挂小树下）:

        1                    4
       / \                  / \
      2   3        →       5   6
                             /
                            1      ← 树变高了！
                           / \
                          2   3
```

**优化**：总是把**矮树挂到高树下**，记录每棵树的高度（rank）。

```java
void union(int x, int y) {
    int rootX = find(x);
    int rootY = find(y);
    if (rootX == rootY) return;

    // 矮的挂到高的下面
    if (rank[rootX] < rank[rootY]) {
        parent[rootX] = rootY;
    } else if (rank[rootX] > rank[rootY]) {
        parent[rootY] = rootX;
    } else {
        // 等高：随便挂一边，被挂的那棵高度 +1
        parent[rootY] = rootX;
        rank[rootX]++;
    }
}
```

```
按秩合并的效果：必须对比"矮挂高" vs "高挂矮"才看得出来

  初始两棵树:
    树 A (高 2)              树 B (高 1)
        1                        4
       / \                      / \
      2   3                    5   6
      |
      7

  验证高度:
    树 A: 1→2→7 = 2 条边，高度 2 ✓
    树 B: 4→5 = 1 条边，高度 1 ✓

union(3, 4): find(3)=1，find(4)=4，核心问题：1 和 4 谁挂谁下面？


  ❌ 错误做法（高树挂矮树，朴素 union 不看高度）:
    把高树 A 的根 1 挂到矮树 B 的根 4 下（根挂根，parent[1]=4）

        4          ← 根变成 4
       /|\
      5 6 1        ← 1 直接挂在 4 下
         / \
        2   3
        |
        7

  结果高度: 4→1→2→7 = 3 条边，高度从 2 长到 3！白长一层
  后果: find(7) 要走 7→2→1→4，3 步，性能恶化


  ✅ 按秩合并（矮树挂高树）:
    把矮树 B 的根 4 挂到高树 A 的根 1 下

        1          ← 根还是 1
       /|\
      2 3 4
      |  / \
      7 5   6

  结果高度: 1→2→7 = 2 条边，高度仍是 2，没长高！
  find(7) 仍只需 7→2→1，2 步，性能保持


  本质:
    矮挂高 → 结果树高 = 高树的高度（不变）
    高挂矮 → 结果树高 = 高树高度 + 1（白长）
    按秩合并永远选前者，让树高增长最慢
```

> **本质**：按秩合并保证树的高度增长极其缓慢。
> n 次 union 后，树高最多 ~log n。光这一个优化就能把 find 压到 O(log n)。

### 4.3 两个优化叠加的协同效应

```
单独路径压缩：均摊 O(log n)（单次最坏 O(n)，可能链状）
单独按秩合并：严格 O(log n)

两者叠加：均摊 O(α(n)) —— 反阿克曼函数
```

#### 为什么单靠路径压缩不够？两个误区

很多人会想："路径压缩不是把树压平到 2 层了吗？为啥不直接 O(1)？" —— 这是并查集最容易被误解的地方。两个原因让它做不到：

**误区一：路径压缩只压平"走过的那条路径"，其他分支原封不动**

用 parent 数组精确表达（比 ASCII 树不易产生对齐歧义）：

```
压缩前的 parent 数组:
  parent[1] = 1   (根)
  parent[2] = 1
  parent[3] = 2
  parent[4] = 3
  parent[5] = 4
  parent[6] = 5
  parent[7] = 6    ← find(7) 的目标
  parent[8] = 5    ← 8 的父是 5，不在 find(7) 的路径上

find(7) 走: 7→6→5→4→3→2→1
路径上经过的节点: 7,6,5,4,3,2,1

压缩后 parent 数组:
  parent[1] = 1
  parent[2] = 1    ← 2 的父从 "1" 变成 "1"（本来就是根，不变）
  parent[3] = 1    ← 3 的父从 "2" 变成 "1"
  parent[4] = 1    ← 4 的父从 "3" 变成 "1"
  parent[5] = 1    ← 5 的父从 "4" 变成 "1"
  parent[6] = 1    ← 6 的父从 "5" 变成 "1"
  parent[7] = 1    ← 7 的父从 "6" 变成 "1"
  parent[8] = 5    ← 8 的父还是 5（没动过！）

深度对比:
  压缩前: find(7) = 7→6→5→4→3→2→1 = 6 步
  压缩后: find(7) = 7→1               = 1 步  ← 直接到根 ✅

  压缩前: find(8) = 8→5→4→3→2→1       = 5 步
  压缩后: find(8) = 8→5→1             = 2 步  ← 5 被压到根，8 被动变浅
```

> 这就是"路径压缩只压平走过的路径"的精确含义:
> 8 不在 find(7) 的路径上，它的 parent 没变（还是 5）。
> 虽然 5 被压到根下了，8 跟着从深度 5 变到深度 2，
> 但 8 没被"压到根"——它仍挂在 5 下面，不是直接挂 1。
>
> 8 要等它自己被 find 过一次，才会被压平到根。

> "压平后全树 2 层"是错觉——只有被 find 经过的那条路径变 2 层，其他分支保持原样。

**误区二：union 会重新长高，把压平的成果毁掉**

更要命的一点。朴素 union 不看高度，可以把一棵压平的树整个挂到一个新节点下面，白长一层：

```
步骤 1: 经过 find 压平后的树（高 2）
        5
      / | | \
     2  1  3  4

步骤 2: 朴素 union(6, 5)，把整棵树挂到 6 下
        6          ← 新根
        |
        5          ← 树高变 3 了！压平成果被毁
      / | | \
     2  1  3  4

步骤 3: find(2) 又要走 2→5→6，3 步（而不是 1 步）
```

每压平一次，下一个 union 又能长高一层。攻击者可以交替构造 union 和 find，让树始终维持在 O(log n) 的深度——这就是均摊卡在 O(log n) 的根源。

> **单次最坏**：O(n)。朴素 union 能造一条 n 层长链，对最深节点 find 一次要走 n 步，那次 find 之后才压平。
> **均摊**：O(log n)。"压平 ↔ 被重新长高"的拉锯战。

#### 两个优化如何协同达到 O(α(n))

回顾误区二的攻击：路径压缩单独用时，union 能把树重新挂高、压平的成果被毁，所以均摊卡在 O(log n)。要突破，必须让 union"挂不高"——这正是按秩合并的活。

```
按秩合并如何破解误区二的攻击:
═══════════════════════════════════════

  误区二的攻击靠的是"union 把高树挂矮树下，白长一层"
  按秩合并强制"矮挂高"后:
    ├── 树高增长极慢: 两棵等高树合并才 +1，
    │   n 个节点最多 log n 次等高合并 → 树高 ≤ log n
    └── 更关键: union 不再"白长"——矮挂高，结果树高 = 高树高度，不增

  → 攻击失效: union 再也造不出"深路径"来抵消 find 的压平


两者的协同（这才是 O(α(n)) 的来源）:
═══════════════════════════════════════

  只有按秩合并:   树高 ≤ log n，但 find 不压平 → 每次 find O(log n)
  只有路径压缩:   find 压平，但 union 重新长高 → 均摊 O(log n)（误区二）

  两者叠加的质变:
    1. 按秩合并 → union 造不出深路径（堵住攻击源头）
    2. 路径压缩 → find 把现存深路径压平
    3. 关键: 因为 union 不再长高，find 压平的成果被【永久保留】
       → 树不仅不增高，还会随 find 次数越来越扁
       → 均摊下来单次操作降到 O(α(n))

  单独任一个都到不了 O(α(n))，必须叠加才有这个质变
```

#### α(n) 到底是什么

```
α(n) 是阿克曼函数 A(m, n) 的反函数。

阿克曼函数增长极快：
  A(0, n)   = n + 1
  A(1, n)   = n + 2
  A(2, n)   = 2n + 3
  A(3, n)   = 2^(n+3) - 3
  A(4, n)   = 2^(2^(2^...)) - 3   ← n+3 层指数塔

反函数 α(n) 增长极慢：

  n               α(n)
  ────────────────────
  < 4                0
  < 16               1
  < 65536            2
  < 2^65536          3
  < 2^(2^65536)      4
  ...

  n = 10^80（宇宙原子总数）时，α(n) ≈ 4

  → 对任何现实规模的数据，α(n) ≤ 5
  → 实际效果就是 O(1)
```

**均摊的直觉**：n 次操作总代价 = O(n · α(n))，均摊到每次 = O(α(n)) ≈ O(1)。类比动态数组的 push——偶尔扩容 O(n)，但 n 次 push 均摊 O(1)；并查集偶尔路径长，但 n 次操作均摊 O(α(n))。

> ⚠️ 注意：路径压缩和按秩合并**不完全相容**。
> 路径压缩会改变树高，rank 不再是真实高度，而是"近似高度"。
> 但这不影响正确性——rank 只是合并时的参考值，矮挂高的大方向仍然有效。

## 五、完整 Java 实现

```java
public class UnionFind {

    private int[] parent;   // parent[i] = i 的父节点
    private int[] rank;     // rank[i]   = 以 i 为根的树的高度（近似）
    private int count;      // 当前集合数

    public UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        count = n;
        for (int i = 0; i < n; i++) {
            parent[i] = i;   // 初始每个元素自成一组
            rank[i] = 1;
        }
    }

    // ===== find：带路径压缩 =====
    public int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);  // 递归找根 + 路径压缩
        }
        return parent[x];
    }

    // ===== union：按秩合并 =====
    public void union(int x, int y) {
        int rootX = find(x);
        int rootY = find(y);
        if (rootX == rootY) return;

        if (rank[rootX] < rank[rootY]) {
            parent[rootX] = rootY;
        } else if (rank[rootX] > rank[rootY]) {
            parent[rootY] = rootX;
        } else {
            parent[rootY] = rootX;
            rank[rootX]++;
        }
        count--;   // 合并一次，集合数 -1
    }

    // ===== 是否同组 =====
    public boolean connected(int x, int y) {
        return find(x) == find(y);
    }

    public int count() {
        return count;
    }
}
```

### 使用示例

```java
public class Main {
    public static void main(String[] args) {
        UnionFind uf = new UnionFind(8);  // 8 个元素 0~7

        uf.union(1, 2);
        uf.union(3, 4);
        uf.union(5, 6);
        uf.union(2, 3);

        System.out.println(uf.connected(1, 4));  // true  (1-2-3-4 已连通)
        System.out.println(uf.connected(1, 5));  // false (5-6 在另一组)
        System.out.println(uf.count());          // 4     (4 个集合)
    }
}
```

## 六、实战应用

### 6.1 Kruskal 最小生成树

```
问题：给一个带权连通图，找一棵权值最小的生成树。

Kruskal 算法:
  1. 所有边按权值排序
  2. 从小到大遍历每条边 (u, v)
  3. 如果 u 和 v 不在同一集合（不会成环）→ 加入生成树，union(u, v)
  4. 加够 n-1 条边结束

并查集的作用:
  第 3 步"是否成环"判断 = connected(u, v)
  → O(α) 完成，比 BFS 判环快得多
```

```java
int kruskal(Edge[] edges, int n) {
    Arrays.sort(edges);   // 按权值排序
    UnionFind uf = new UnionFind(n);
    int totalWeight = 0, edgeCount = 0;

    for (Edge e : edges) {
        if (!uf.connected(e.u, e.v)) {
            uf.union(e.u, e.v);
            totalWeight += e.weight;
            if (++edgeCount == n - 1) break;
        }
    }
    return totalWeight;
}
```

### 6.2 岛屿数量（LeetCode 200）

```
问题：二维网格里 '1' 是陆地，'0' 是水，数有几个岛屿（连通的 '1' 算一个）。

并查集做法:
  遍历每个 '1'，和它左边/上面的 '1' union
  最后 count() 就是岛屿数

class Solution {
    public int numIslands(char[][] grid) {
        int m = grid.length, n = grid[0].length;
        UnionFind uf = new UnionFind(m * n);
        int water = 0;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == '0') {
                    water++;
                    continue;
                }
                int idx = i * n + j;
                // 只看左和上，避免重复 union
                if (i > 0 && grid[i-1][j] == '1') uf.union(idx, idx - n);
                if (j > 0 && grid[i][j-1] == '1') uf.union(idx, idx - 1);
            }
        }
        return uf.count() - water;
    }
}
```

### 6.3 冗余连接（LeetCode 684）

```
问题：一棵树多加了一条边，找出那条导致成环的边。

思路:
  逐条遍历边 (u, v)
  如果 connected(u, v) == true → 这条边成环了，返回它
  否则 union(u, v)

  一行核心逻辑:
    if (uf.connected(u, v)) return new int[]{u, v};
    uf.union(u, v);
```

### 6.4 账户合并（LeetCode 721）

问题：多个账户列表，如果两个账户有公共邮箱就合并成一个。

思路:
  email → 第一次出现的账户下标
  遍历每个账户的邮箱，和第一个邮箱 union
  最后按连通分量收集邮箱

## 七、与红黑树/堆/跳表的串联

```
四种"自平衡/自适应"策略的对照:

┌──────────┬─────────────────────┬──────────────────┐
│ 数据结构  │ 平衡策略              │ 单次操作复杂度    │
├──────────┼─────────────────────┼──────────────────┤
│ 红黑树    │ 旋转 + 变色（强制）   │ 严格 O(log n)    │
│ 跳表      │ 随机层数（概率）      │ 期望 O(log n)    │
│ 堆        │ 上浮/下沉 + 完全性    │ 严格 O(log n)    │
│ 并查集    │ 路径压缩 + 按秩合并   │ 均摊 O(α(n)) ≈ O(1) │
└──────────┴─────────────────────┴──────────────────┘


四种"用数组表达树形结构"的对照:

┌──────────┬─────────────────────────────────────┐
│ 堆       │ 数组存完全二叉树，下标公式寻父子      │
│          │ parent(i) = (i-1)/2, left(i) = 2i+1  │
│          │ 树形固定，公式不变                    │
├──────────┼─────────────────────────────────────┤
│ 并查集    │ 数组存森林，parent[i] 直接查父亲     │
│          │ 树形动态变化，靠 parent 数组实时维护  │
├──────────┼─────────────────────────────────────┤
│ 跳表     │ 用 next[] 数组存多层后继              │
│          │ 层数随机，每个节点 next 长度不同       │
└──────────┴─────────────────────────────────────┘
```
