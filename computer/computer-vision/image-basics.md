# 图像如何变成数字（Image Basics）

> 记录日期：2026-09-10
> 讲解人：AI（Claude）

## 一、直观理解

**计算机不认识"猫"长什么样，它只认识数字。** 所以想让计算机识别猫，第一步是问：一张照片，怎么变成计算机能处理的数字？

答案是：**一张图 = 一个巨大的数字矩阵（表格）。**

```
一张 640×480 的彩色照片
        ↓
    ┌─────────────┐
    │ 像素(0,0)    │ 像素(0,1)    ...   ← 每一格叫一个 像素 (pixel)
    │ 像素(1,0)    │ 像素(1,1)    ...
    │   ...       │   ...        ...
    └─────────────┘
    高 480 行 × 宽 640 列 = 307,200 个像素
```

> **像素 = 图像的最小单位**，是图像这个"数字表格"里的一格。每个格子里存着一个数（灰度图）或三个数（彩色图）。

---

## 二、灰度图：一格一个数

如果你拍一张**黑白照片**，每个像素只需要存一个数：**亮度**。

| 数值 | 含义 |
|------|------|
| 0 | 纯黑 |
| 255 | 纯白 |
| 128 | 中等灰 |

这个数的范围叫 **灰度 (grayscale)**，通常用 0\~255 表示（即 8 位，$2^8=256$ 个级别）。

```
灰度图 = 一个 2 维矩阵（行 × 列），每格一个 0~255 的数

  [[  0, 255, 255,   0],
   [  0, 255, 255,   0],
   [255,   0,   0, 255]]
```

比如上面这个 3×4 的矩阵，画出来就是一个"黑—白—白—黑"间隔的图案。**你看它像什么，取决于那些 255 的格子怎么排列。**

> **灰度图 = 二维数字矩阵。** 模式识别本质就是：在这堆数字里找"有规律的结构"。

---

## 三、彩色图：一格三个数

彩色照片每个像素需要存**三个数**，分别表示三种颜色分量的强度。最常用的是 **RGB**：

| 通道 | 全称 | 含义 |
|------|------|------|
| R | Red 红 | 红色分量 (0\~255) |
| G | Green 绿 | 绿色分量 (0\~255) |
| B | Blue 蓝 | 蓝色分量 (0\~255) |

```
彩色图 = 3 个二维矩阵叠在一起，每个像素是一组 (R, G, B)

  R 通道        G 通道        B 通道
 [[255, 0],    [[0, 255],    [[0, 0],
  [0, 0]]       [0, 0]]       [255, 255]]
     ↓            ↓             ↓
      组合起来 →  (255,0,0) 是红色，(0,255,0) 是绿色，(0,0,255) 是蓝色
```

**混合三原色能得到几乎所有颜色**（加色法）：

| (R, G, B) | 颜色 |
|-----------|------|
| (255, 0, 0) | 红 |
| (0, 255, 0) | 绿 |
| (0, 0, 255) | 蓝 |
| (255, 255, 255) | 白 |
| (0, 0, 0) | 黑 |
| (255, 255, 0) | 黄 |

> 所以一张彩色图的存储大小 = 宽 × 高 × 3。640×480 的彩色图 = 640×480×3 ≈ 92 万个数字。

## 四、坑：OpenCV 用的是 BGR，不是 RGB

你用其他工具（PIL、matplotlib）读图得到 RGB，但 **OpenCV 读图得到 BGR**——红和蓝顺序反了。

```
PIL/matplotlib:  (R, G, B)
OpenCV:          (B, G, R)   ← 历史遗留，为了兼容老格式
```

**后果**：用 OpenCV 读图，再用 matplotlib 直接显示，颜色会"红蓝互换"（天空变橙色）。解决办法是转换：`cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`。

> **写代码时先记住：用 OpenCV 处理图，通道顺序是 BGR。** 转来转去容易出错，这是 CV 新手最常见的第一个坑。

## 五、其他关键概念

### 分辨率与尺寸

| 概念 | 含义 |
|------|------|
| 分辨率 | 宽×高（如 640×480、1920×1080） |
| 像素总数 | 宽×高（决定"多清晰"） |
| 宽高比 | 宽÷高（4:3、16:9） |

### 位深（bit depth）

上面说灰度用 0\~255，那是 **8 位**。有些传感器用 10/12/14/16 位，能记录更精细的明暗层次（摄影、工业检测里重要），但一般深度学习里归一化到 0\~1 或 0\~255 用。

### 图像 → 数据给神经网络的形状

深度学习里，一张图通常组织成：

```
(batch, height, width, channels)     # TensorFlow 风格
(batch, channels, height, width)     # PyTorch 风格
```

一张 640×480 的 BGR 彩色图 → 形状 `(1, 3, 480, 640)`（PyTorch 习惯），三个通道排在最前面。

## 六、预处理（Preprocessing）：喂给模型的"标准格式"

原始照片不能直接喂给模型，要先统一格式。四个最常见的操作：

| 操作 | 做什么 | 为什么 |
|------|--------|--------|
| **Resize 缩放** | 统一到固定尺寸（如 640×640） | 模型输入尺寸固定 |
| **Normalize 归一化** | 像素从 0~255 缩放到 0~1（或 -1~1） | 数值范围小，梯度更稳，训练更快 |
| **灰度化/色彩转换** | 灰度图、HSV、YCbCr 等 | 有的任务不需要颜色，或某些颜色空间更好分 |
| **数据增强** | 随机翻转/旋转/调亮度/裁剪 | 训练时"造"更多样本，防过拟合、提鲁棒性 |

**归一化的必要性**（和梯度下降笔记连起来想）：权重更新用梯度，如果输入都是 0\~255 的大数，梯度也大，容易震荡不收敛；缩放到 0\~1 后训练稳定得多。

> **预处理 = 把"照片"翻译成"模型能消化的标准输入"。**

## 七、从"数字"到"特征"：下一步预告

到现在，图像只是一堆数字。怎么从这堆数字里**找到"猫"的特征**？

答案分两步，也是后面两篇笔记：

1. **手工设计特征**（传统方法，如 Haar、HOG）——人告诉程序"猫耳朵是三角形"这类规则。
2. **卷积神经网络自动学特征**（深度学习）——给模型大量"猫/非猫"图片，让它自己学会"什么数字组合代表猫"。

> **图像识别史 = 从"人设计特征"到"模型自己学特征"的历史。** 下一篇笔记进入卷积神经网络，看模型是怎么自己学会"看"的。
