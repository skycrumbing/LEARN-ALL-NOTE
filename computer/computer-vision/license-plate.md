## 一、直观理解：车牌识别的全流程

车牌识别（LPR / ANPR，License Plate Recognition）是最典型的**端到端工程**问题，它把前面学的几乎全用上了：

```
输入车辆照片
   ↓
① 车牌检测：找出车牌在画面哪里（一个目标检测任务）
   ↓
② 字符分割：把车牌区域切成一个个字符（可做可不做，端到端模型省掉这步）
   ↓
③ 字符识别：逐个认出字符（本质是图像分类/序列识别）
   ↓
输出："京A12345"
```

> **车牌识别 = 检测(定位车牌) + OCR(读字符)。** 前面学的检测恰好解决第①步。

---

## 二、传统方法：颜色 + 边缘 + 形态学（不需要深度学习）

第①步"车牌定位"的传统思路，完全不用神经网络：

```
① 颜色筛选：蓝色/绿色/黄色 车牌在 HSV 空间里筛出来
   （中国蓝牌是蓝色底白字，颜色特征极强）
      ↓
② 边缘检测 + 二值化：找"字与底色对比强烈"的区域
      ↓
③ 形态学操作：膨胀让文字连成块，形成"白板"
      ↓
④ 轮廓查找：找"宽高比约 3~5 的矩形区域"（车牌是扁长的）
      ↓
⑤ 宽高比过滤：扔掉不是车牌的矩形
```

| 手段 | 解决什么 |
|------|---------|
| 颜色筛选 (HSV) | 车牌有固定底色，是最强先验 |
| 边缘+形态学 | 把文字区域"糊"成一个整体块 |
| 宽高比过滤 | 车牌≈440×140mm，比例固定，能滤掉大量噪声 |

> **传统方法的价值：零训练、极快、适合规则固定的场景。** 代码 `07_license_plate.py` 就实现了这条路。缺点：光线/倾斜/遮挡下不稳。

## 三、深度学习方法：端到端 LPRNet

传统"检测→分割→识别"三步每一步都可能出错。深度学习想直接一步到位：

### LPRNet（2018）：CNN + 序列模型 + CTC

```
车牌图片 → CNN 提取特征 → 按列生成字符序列 → CTC 解码 → "京A12345"
```

```
┌─────────┐     ┌─────┐     ┌──────────┐     ┌─────┐
│ 车牌图片  │ →  │ CNN │ →  │ LSTM 序列  │ →  │ CTC │ → 字符序列
│(高21)     │     │特征图│     │(从左到右读)│     │解码 │
└─────────┘     └─────┘     └──────────┘     └─────┘
```

**关键：为什么不先分割字符？** 字符可能粘连、角度变形、模糊，先分割容易出错。LPRNet **不分割**，而是像"读一行文字"一样，让 CNN 对每一列输出一个"当前在念哪个字符"，再用 CTC 对齐出最终字符串。

### CTC Loss：让模型学会"对齐"

CTC 解决一个问题：**模型输出的长度 ≠ 车牌字符个数**（图里 7 个字符，但网络可能输出 40 列）。

CTC 的思路：

- 每个时刻网络输出一个概率分布（可能是字符、也可能是"空格"-）
- 引入特殊符号 **blank (-)** 表示"当前没有字符"
- 训练时穷举所有可能的"帧→字符"对齐方式，取概率之和作为该标签的概率
- 解码时：合并重复字符 → 去掉 blank

```
原始输出:  京 京 - 京 A A - 4 5 - 5 2 3
合并重复:   京  - 京 A - 4 5 - 5 2 3
去掉blank: 京 A 4 5 5 2 3
```

**这就是语音识别 (ASR) 用的同一个技术**——车牌识别、语音转文字、手写识别本质是同一类"序列对齐"问题。

## 四、中国车牌的结构（识别目标长什么样）

要识别，先知道目标结构：

| 位 | 内容 | 例子 |
|----|------|------|
| 第 1 位 | 省份简称（汉字，31 个省） | 京、粤、沪 |
| 第 2 位 | 发牌机关字母（I/O 除外） | A（省会）、B |
| 第 3~7 位 | 5 位序号（数字+大写字母，字母中不用 I/O） | 12345、AB123 |

```
车牌字符集 = 31 汉字 + 24 大写字母 + 10 数字 ≈ 65 类
```

| 车牌类型 | 底色 | 用途 |
|---------|------|------|
| 蓝底白字 | 蓝 | 普通燃油车 |
| 绿底黑字 | 绿 | 新能源（6 位号码） |
| 黄底黑字 | 黄 | 大型车、货车 |
| 白底黑字 | 白 | 军警车 |

> **汉字类特别多（31 个）且字形复杂，是识别里最难的部分，通常单独加大汉字训练权重。**

## 五、工程实现路径（实际项目怎么选）

| 方案 | 组成 | 适用 |
|------|------|------|
| 传统 | 颜色/轮廓定位 + 字符分割 + 每字符 CNN 分类 | 固定摄像头、蓝牌、速度要求极高 |
| 半深度 | YOLO 检测车牌 + 字符分类 CNN（或 OCR） | 通用、灵活 |
| 端到端 | LPRNet / 检测+识别一体的模型 | 效果好、抗干扰强 |

**完整 LPR 系统还需要**：车牌**矫正**（透视变换把歪的拉正，利用四点）、**追踪**（视频里连续帧结果投票，减少单帧误读）、**置信度过滤**（低分结果丢弃）。

> **工程上常见坑：** 车牌颜色模型在灯光下发紫、倾斜车牌宽高比不对、新能源 6 位号码、泥污遮挡——所以要上矫正 + 多帧融合 + 数据增强。

## 六、本篇一句话总结

| 概念 | 一句话 |
|------|--------|
| LPR 全流程 | 检测车牌 →（分割）→ 识别字符 |
| 传统定位 | 颜色筛选 + 边缘 + 形态学 + 宽高比过滤 |
| LPRNet | CNN+LSTM+CTC 端到端，不做字符分割 |
| CTC | 用 blank 符号让模型学会"帧→字符"对齐 |
| 中国车牌 | 省汉字 + 字母 + 5 位（新能源 6 位），字符集约 65 类 |
| 与语音识别同源 | CTC 也是 ASR 的核心技术，跨领域串联 |
