# 浮点数：二进制无法精确表示怎么办？

## 问题回顾

$0.1_{10}$ 在二进制中是无限循环小数 $0.0001100110011...\ _2$，计算机无法精确存储。

但现实世界需要处理小数，怎么办？主要有以下几种方案。

---

## 方案一：IEEE 754 浮点数标准（最常用）

这是计算机最主流的方案，几乎所有编程语言中的 `float` / `double` 都采用此标准。

### 核心思路：用有限位"近似"存储

以 64 位双精度浮点数为例：

```
┌─ 1 位 ─┬─ 11 位 ─┬──────── 52 位 ─────────┐
│ 符号位  │  指数位  │      尾数位            │
│   ±     │  ×2^exp  │  有效数字（二进制）    │
└─────────┴──────────┴────────────────────────┘
```

公式：$(-1)^{sign} \times (1 + mantissa) \times 2^{exponent}$

### 三部分拆解：用具体例子理解

用 **5.75₁₀** 在 32 位 float 中如何存储来一步步拆解：

#### 第一步：符号位（1 位）

```
0 → 正数
1 → 负数
```

5.75 是正数，所以符号位 = **0**。

#### 第二步：转成二进制科学记数法

```
5.75₁₀ = 101.11₂ （整数 5=101₂，小数 0.75=0.11₂）
```

写成二进制科学记数法（小数点移到第一位后面）：

```
101.11₂ = 1.0111₂ × 2²
```

#### 第三步：尾数位（存储小数点后的部分）

尾数存储的是**科学记数法中小数点后面的部分**（叫"尾数"或"有效数字"）。

```
1.0111₂ × 2²
  ↑
  这个 1 是隐含的，不存！只存 0111
```

> 为什么隐含 1？因为二进制科学记数法下，第一位总是 1，所以没必要存，省出 1 位精度。

float 有 23 位尾数，不够的补 0：

```
尾数 = 0111 0000 0000 0000 0000 000
      ↑ 实际有效位      ↑ 补零填充
```

#### 第四步：指数位（存储指数，需要偏移）

指数是 2，但不能直接存 2，因为指数可以是负数（比如 0.125 = 1.0 × 2⁻³）。

IEEE 754 用**偏移量**来解决：存的是 `实际指数 + 偏移量`。

| 类型 | 指数位数 | 偏移量 |
|------|---------|--------|
| float | 8 位 | 127 |
| double | 11 位 | 1023 |

```
实际指数 = 2
偏移量   = 127
存储值   = 2 + 127 = 129₁₀ = 10000001₂
```

#### 完整拼装

以 32 位 float 为例，5.75 的存储：

```
┌─ 1 位 ─┬──── 8 位 ────┬──────── 23 位 ───────────────┐
│   0    │  10000001    │ 0111 0000 0000 0000 0000 000 │
│ 正数   │  指数 2+127  │  尾数 1.0111 的 .0111 部分   │
└────────┴──────────────┴──────────────────────────────┘
```

#### 逆向验证：从存储还原数字

```
符号位 0         → 正数
指数 10000001₂   → 129 - 127 = 2
尾数 0111...     → 前面补隐含 1 → 1.0111₂

1.0111₂ × 2² = 101.11₂ = 5.75₁₀ ✅
```

### 为什么指数要偏移——一个直观对比

| 实际指数 | 存储值（float，+127） | 二进制 |
|---------|---------------------|--------|
| 3 | 130 | 10000010 |
| 2 | 129 | 10000001 |
| 1 | 128 | 10000000 |
| **0** | **127** | **01111111** |
| -1 | 126 | 01111110 |
| -2 | 125 | 01111101 |
| -126 | 1 | 00000001 |

**好处**：不需要单独的符号位来表示指数正负，比较两个浮点数大小时，可以直接按位比较（先比符号位，再比指数，再比尾数）。

### 特殊值

指数位全 0 和全 1 有特殊含义：

| 指数 | 尾数 | 含义 |
|------|------|------|
| 全 0 | 全 0 | **0**（正零 / 负零） |
| 全 0 | 非 0 | **非规格化数**（接近 0 的极小值） |
| 全 1 | 全 0 | **无穷大**（Inf，正负） |
| 全 1 | 非 0 | **NaN**（Not a Number，如 0/0） |

### 三部分总结

| 部分 | 作用 | 类比十进制 |
|------|------|-----------|
| 符号位 | 表示正负 | 前面的 ± 号 |
| 指数位 | 表示小数点移动了多少位 | $10^2$ 中的 2 |
| 尾数位 | 表示有效数字（隐含前导 1） | 科学记数法 $1.23 \times 10^2$ 中的 1.23 |

### 为什么 0.1 + 0.2 ≠ 0.3？

```
0.1₁₀ ≈ 0.00011001100110011001100110011001100110011001100110011010... (截断到 52 位)
0.2₁₀ ≈ 0.00110011001100110011001100110011001100110011001100110100...

相加后 ≈ 0.30000000000000004₁₀
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 硬件直接支持，速度极快 | 有精度误差，不适合金融计算 |
| 范围极大（$10^{-308} \sim 10^{308}$） | 比较相等时要小心（用差值比较） |
| 所有现代 CPU 统一标准 | 累积误差会越来越大 |

### float vs double：都是近似，精度不同

`float`（32 位）和 `double`（64 位）都遵循 IEEE 754 标准，**都不能完美表示十进制小数**，但精度和范围不同：

| 对比项 | float（单精度） | double（双精度） |
|--------|----------------|-----------------|
| 总位数 | 32 位 | 64 位 |
| 符号位 | 1 位 | 1 位 |
| 指数位 | 8 位 | 11 位 |
| 尾数位 | **23 位** | **52 位** |
| 十进制精度 | 约 **7 位**有效数字 | 约 **16 位**有效数字 |
| 范围 | $\pm 3.4 \times 10^{38}$ | $\pm 1.8 \times 10^{308}$ |
| 内存 | 4 字节 | 8 字节 |
| 速度 | 更快（内存带宽小） | 较慢（但现代 CPU 差距很小）|

**同一个数，两种精度：**

```python
# 0.1 在 float 和 double 中都是近似值，但截断位置不同
# float  (32 位) → 0.1 ≈ 0.100000001490116119384765625
# double (64 位) → 0.1 ≈ 0.1000000000000000055511151231257827021181583404541015625
```

**关键结论：** 两者都不能完美表示 0.1，只是 double 的近似更精确。

**实际选择：**

```python
# ✅ 日常开发用 double（Python 的 float 就是 double）
pi = 3.141592653589793

# ❌ 除非以下情况才用 float
# - 移动端 / GPU 显存受限
# - 大量数组运算（机器学习模型权重）
# - 嵌入式系统
import numpy as np
data = np.float32([0.1, 0.2, 0.3])  # 节省一半内存
```

大多数语言中 `float` 是 32 位，`double` 是 64 位：

| 语言 | float | double |
|------|-------|--------|
| C / C++ | `float` | `double` |
| Java | `float` | `double` |
| C# | `float` | `double` |
| Python | 没有 float（只有 double） | `float`（就是 double） |
| JavaScript | 没有 float（只有 double） | `Number`（就是 double） |

> ⚠️ Python 和 JavaScript 的 `float` 实际上就是 double——它们舍弃了单精度，因为对大多数场景来说，省那 4 字节不值得。

### 工程实践：如何安全比较浮点数

```python
# ❌ 不要这样
if a == b:
    ...

# ✅ 要这样
EPSILON = 1e-9
if abs(a - b) < EPSILON:
    ...
```

## 方案二：十进制浮点数（Decimal）

用十进制存储，而不是二进制。本质上是用整数模拟十进制。

### Python 示例

```python
from decimal import Decimal

# ❌ 二进制浮点数的问题
0.1 + 0.2  # 0.30000000000000004

# ✅ 十进制浮点数
Decimal('0.1') + Decimal('0.2')  # Decimal('0.3') 精确！
```

### 应用场景

- **金融计算**：银行、会计、税务（不允许一分钱误差）
- **货币运算**：价格、折扣、汇率计算

### 优缺点

| 优点 | 缺点 |
|------|------|
| 精确的十进制运算 | 比二进制浮点数慢（软件模拟） |
| 符合人类直觉 | 占用更多内存 |
| 适合金融场景 | 不是所有编程语言都内置支持 |

---

## 方案三：定点数（Fixed-Point）

把所有小数乘以一个固定倍数，变成整数来存储。

### 示例：用整数表示货币

```python
# 用「分」代替「元」，所有运算都是整数
price = 1999  # 实际是 ¥19.99
count = 3
total = price * count  # 5997 分 = ¥59.97
```

### 应用场景

- **嵌入式系统**：没有浮点运算单元的 MCU
- **游戏中的坐标**：用 16.16 定点数表示位置
- **早期计算机**：在没有硬件浮点运算时使用

### 优缺点

| 优点 | 缺点 |
|------|------|
| 纯整数运算，速度极快 | 精度由固定小数位决定 |
| 没有舍入误差 | 容易溢出（需要小心范围） |
| 适合硬件实现 | 除法时需要额外处理 |

---

## 方案四：分数表示（Rational）

用分子/分母的形式精确存储有理数。

### Python 示例

```python
from fractions import Fraction

Fraction('0.1') + Fraction('0.2')
# Fraction(3, 10)  → 精确的 3/10
```

### 应用场景

- **符号计算**：数学软件（Mathematica、SymPy）
- **代数运算**：需要保持精确结果时

### 优缺点

| 优点 | 缺点 |
|------|------|
| 有理数运算完全精确 | 连续运算后分子分母会变得巨大 |
| 不丢失精度 | 不适用于无理数（如 $\pi$、$\sqrt{2}$） |
| 适合数学推导 | 性能开销大 |

---

## 方案五：高精度浮点数（Arbitrary Precision）

根据精度需求动态分配更多位数，而不是固定 32/64 位。

### 示例

```python
# Python 的 decimal 可以设置任意精度
from decimal import Decimal, getcontext

getcontext().prec = 50  # 50 位有效数字
Decimal(1) / Decimal(3)  # 0.33333333333333333333333333333333333333333333333333
```

### 应用场景

- **科学计算**：需要极高精度时
- **密码学**：大数运算
- **数学研究**：计算 $\pi$ 的百万位

---

## 方案对比总结

| 方案 | 精度 | 速度 | 适用场景 |
|------|------|------|----------|
| IEEE 754 浮点数 | 近似值 | ⚡ 极快（硬件） | 通用计算、科学计算、游戏 |
| 十进制浮点数 | 精确十进制 | 🐢 较慢（软件） | 金融、货币计算 |
| 定点数 | 固定精度 | ⚡ 极快（整数） | 嵌入式、游戏坐标 |
| 分数表示 | 精确有理数 | 🐢 慢 | 数学软件、符号计算 |
| 高精度浮点数 | 任意精度 | 🐢 越精确越慢 | 科研、密码学 |

## 实际工程中的选择

### 日常开发（通用场景）

```python
# 1. 普通计算用 float，够用
result = 0.1 + 0.2

# 2. 比较时用容差
if abs(result - 0.3) < 1e-9:
    print("相等")

# 3. 输出时格式化
print(f"{result:.2f}")  # 0.30
```

### 金融场景

```python
# 全程用 Decimal
from decimal import Decimal

price = Decimal('19.99')
tax_rate = Decimal('0.13')
total = price * (Decimal('1') + tax_rate)
```

### 嵌入式 / 性能敏感场景

```c
// 用定点数，单位是 1/1000
int32_t speed = 12345;  // 实际是 12.345
int32_t time = 2000;    // 实际是 2.000
int32_t distance = speed * time;  // 结果再除以 1000
```

---

## 一句话总结

> 没有完美的方案，只有适合场景的取舍。通用计算用 IEEE 754（够用且最快），金融用 Decimal，嵌入式用定点数，数学用分数。
